Refresh / Content Opportunity Scoring

A machine-learning approach for prioritizing content pages for refresh review

Abstract

This study asks whether historical search, content, traffic, and engagement signals can be used to prioritize pages for potential content-refresh review. A Logistic Regression model was trained to distinguish pages associated with declining trends and was evaluated against a simple baseline using a grouped train/test split. The model uses search-demand, content, traffic, engagement, and categorical content signals while excluding direct trend fields from the predictive features. The resulting probabilities are combined with impression volume to produce a ranked list of content pages for human review. The results provide a repeatable prioritization framework for content planning, while the analysis does not claim causal effects or explain search-engine algorithms.

Introduction and Problem Statement

Content teams often have more pages available for review than they can manually evaluate. A useful prioritization system can help identify pages that deserve attention based on measurable search and engagement signals.

This research investigates whether historical content, search, traffic, and engagement signals can be used to prioritize pages associated with declining performance. The goal is not to prove why a page declined, but to create a repeatable decision-support method for determining which pages should be reviewed first.

Research Question

Can historical search and content-performance signals be used to identify pages that are growing, declining, recovering, or worth review, and rank them for content-refresh actions?

Data

The analysis uses the anonymized FlyRank Machine Learning Internship dataset. The working dataset contains 30,000 content records and 44 available fields.

The analysis uses search-demand, content, traffic, engagement, and trend-related fields available in the dataset. The dataset was inspected for missing values and duplicate records before modeling. No duplicate rows were identified during the analysis.

The target label was derived from the recorded trend direction. Pages with a trend direction of down were treated as refresh candidates for the binary prioritization task.

Public-data safety: This paper does not expose client names, domains, URLs, private queries, credentials, or raw client exports.

Methodology

Target Label

The target variable is refresh_candidate. A value of 1 represents a page whose recorded trend direction is down. Other recorded trend directions are represented as 0.

Features

The model uses available search, content, traffic, and engagement signals including search volume, competition, CPC, word count, character count, impressions, clicks, pageviews, sessions, users, engaged sessions, AI sessions, days with impressions, days with sessions, CTR, average position, engagement rate, scroll rate, AI traffic percentage, content type, main intent, provider metadata, and model metadata.

Direct trend fields and identifiers were excluded from the model inputs. In particular, content_id, client_id, trend_direction, and trend_pct were not used as predictive features.

Model

A Logistic Regression classifier was selected as a simple and interpretable supervised-learning model. Numerical missing values were handled using median imputation and standardization. Categorical variables were imputed using the most frequent category and encoded using one-hot encoding.

Validation

The dataset was divided into training and testing subsets using an 80/20 grouped split. Client identifiers were used only to create groups, reducing the risk of records from the same client appearing in both training and testing data.

Baseline

The Logistic Regression model was compared against a simple prior-probability baseline using the same test data.

Results

The Logistic Regression model performed better than the baseline across all reported metrics. However, the improvement is modest, so the model should be treated as a prioritization aid rather than a highly accurate predictive system.

Model Accuracy ROC-AUC PR-AUC
Logistic Regression 0.5471 0.5688 0.5711
Baseline 0.5110 0.5000 0.5110

The ROC-AUC of 0.5688 is above the baseline value of 0.5000, while the PR-AUC of 0.5711 is above the baseline value of 0.5110. This indicates that the model contains some useful signal for prioritization, although its predictive strength is limited.

Ranked Content Recommendations

The trained model produces a refresh probability for each content record. This probability is combined with 90-day impression volume to calculate an impact score. Records with higher impact scores are placed higher in the review queue.

Recommended Review Process

  1. Very High priority: Review first for content freshness, search-intent alignment, outdated information, content depth, and internal linking.
  2. High priority: Review after the Very High priority group.
  3. Review: Keep in a monitoring queue and reassess periodically.

The ranked recommendations are generated directly from the capstone notebook. Content IDs are anonymized and are intended only as identifiers within the dataset.

Limitations and Honest Framing

The target label is based on the observed trend_direction field rather than a separately measured future outcome. Therefore, the model should be interpreted as a prioritization model rather than a guaranteed prediction of future performance.

The dataset contains aggregated 90-day performance signals. These signals may describe the same period associated with the observed trend, so the results should not be interpreted as evidence of causal relationships.

The model is trained and evaluated on the available FlyRank internship dataset. Its performance may not generalize to other datasets, clients, industries, or time periods.

The analysis does not prove how Google or another search engine algorithm works, and it does not establish that refreshing a page will cause its search performance to improve.

Reproducibility

The analysis was implemented in the capstone notebook using Python and standard machine-learning libraries. The workflow includes data loading, data inspection, preprocessing, grouped train/test validation, Logistic Regression training, baseline comparison, evaluation, and ranked recommendation generation.

The completed capstone notebook is maintained in the project repository under the work/ directory. The raw dataset is stored in the repository's data structure as the anonymized internship dataset used for this analysis.

Decision Supported

This analysis supports the decision of which content pages should be prioritized for human review or potential refresh. The output is intended to make content-planning decisions more systematic and repeatable.
